# 正式版の技術選定

作成日：2026年11月18日。現時点の要件に基づく選定。実装状況は `production-development.md` を参照。

## 納品・動作条件

ビルド済みHTML・CSS・JavaScript・JSON・画像をZIPで納品する。設置先では展開して静的Webサーバーで配信するだけとし、Node.js、npm、Python、PHP、データベース、コンテナを実行環境の必須条件にしない。

HTTPSを正式運用の条件とする。現在地取得には安全なコンテキストと利用者の許可が必要。HTMLのダブルクリックでの実行や完全オフライン動作は今回の対象外。背景地図等の外部サービスへの通信は必要。

サブディレクトリへの設置を想定し、Viteのbaseは `./`。データ・画像の参照も設置先の相対パスを基準にする。画面切り替えのためのサーバー側URL書き換えは不要とする。スポットへのリンクはハッシュ形式で扱い、住所・現在地はURLへ含めない。

## 採用案

| 領域 | 選定 | 理由・使い方 |
| --- | --- | --- |
| UI | Vue 3 / Composition API | 検索条件、件数、一覧、地図、詳細の連動を状態から管理。既存HTMLの見た目を段階的に移植できる |
| 言語 | TypeScript | スポット・座標・掲載状態などの取り違えを開発時に検出する |
| ビルド | Vite + npm / lockfile | 開発環境で静的ファイルを生成。サーバーには生成物だけを設置する |
| 地図 | Leaflet 1.9.4 | 現行機能を継承し、ポイント表示・ポップアップ・範囲調整に使用。調査時の公式安定版。2系ベータは採用しない |
| Vueと地図の接続 | 自前の小さなVueコンポーネント | Leafletの生成・破棄、選択、マーカー更新を集約。追加ラッパーへの依存を増やさない |
| レイアウト | 通常のCSS / Grid / Flexbox | 地図と一覧の領域サイズ、スクロール、スマートフォン表示を制御。UIフレームワークは導入しない |
| 状態管理 | Vueのref・computedとcomposable | 現在の画面規模ではPiniaは不要。フィルター・選択スポット・検索起点を集約する |
| 検索 | JavaScriptによるローカル検索 | 数十〜数百件を想定。文字列正規化、空白区切りAND検索、分類・タグ・区の絞り込みを実装。専用検索サーバーは不要 |
| 距離 | 直線距離の計算関数 | 周辺候補の絞り込みと距離順に使用。徒歩距離とは表示を分ける |
| 公開データ | UTF-8 JSON + ローカルWebP画像 | 元データから公開可能な情報だけを書き出す。CSVパーサーを閲覧者側で動かさない |
| データ検証 | Zod（生成・検証時） | ID重複、座標、必須項目、掲載状態と画像の参照を確認。TypeScriptだけでは外部データを検証できないため補う |
| ロジックテスト | Vitest | 絞り込み、距離、掲載対象判定の境界条件を確認 |
| 画面テスト | Playwright（開発時のみ） | PC・スマートフォンの最終カード選択、詳細復帰、検索、サブディレクトリ配置等を検証 |

Vue以外のパッケージも含め、実装開始時に安定版の互換性を確認し、実際に使用するバージョンをlockfileで固定する。テスト・生成ツールは設置先では不要。

## 他方式との比較

| 方式 | 判断 |
| --- | --- |
| 現行の単一HTMLと直接DOM操作を継続 | 移行は小さいが、検索条件・非同期処理・地図と詳細の状態が増えたため、正式版では役割を分割する |
| Vue + Vite | 推奨。静的配信と、複数UIの状態連動を両立できる |
| React + Vite | 同じ納品条件を満たす有力候補。引継ぎ先がReact中心なら変更可能。今回の要件だけではVueより優先する理由はない |
| Next.js / Nuxt | 静的出力も可能だが、現状はSSR・サーバー処理・多数ページのルーティングを必要としていないため採用しない |
| MapLibre GL JS | ベクトル地図の詳細なスタイル制御が主目的になった場合の候補。今回のポイント地図ではLeafletを継承する |

## 外部サービスの方針

### 背景地図

初期候補は地理院タイルの淡色地図。日本国内の地図としての読みやすさを実画面で確認して確定する。出典リンクを表示し、URL・出典・最大ズームは設定ファイルから変更可能にする。

OSM標準タイルは現行版で使用しているが、公式ポリシーはベストエフォートで可用性保証がないことを明記している。正式版の背景地図と地図描画ライブラリの選定は分けて扱う。地理院タイルについても可用性を独自に保証するものではない。

### 住所検索

住所検索を独立した関数に分離し、送信先を差し替え可能にする。現行の国土地理院住所検索エンドポイントは、正式利用条件・継続提供・CORS・検索精度を追加確認するまで本番採用を確定しない。地理院タイルの利用条件から住所検索APIの利用条件を推定しない。

無償かつAPIキー不要を優先する案と、契約型サービスを使う案では、継続性・費用・キー制限の条件が異なる。秘密のAPIキーを要するサービスは静的ZIPだけでは安全に秘匿できないため、ブラウザ向け公開キーをドメイン制限等で利用できるサービスを選ぶか、機能を初期公開から外す。代理サーバーが必要なサービスは今回の納品条件に合わない。

### 現在地

ブラウザ標準Geolocation APIを使用。操作時に取得し、拒否・時間切れの場合も通常検索を利用できるようにする。正確な座標や入力住所をアプリ側で永続保存しない。外部送信は使用する地図・検索・経路サービスの仕様に応じて説明する。

### 徒歩ルート

正式版の第一案は、個別スポットから外部地図サービスの経路案内を開く方式。地図内の徒歩経路表示は現行版からの仕様変更となるため、採用前に確認する。

地図内表示を維持する場合は、利用条件・CORS・ブラウザ向けキー・上限・費用を確認した経路APIを確定してから組み込む。現行の公共OSRMエンドポイントを、そのまま正式運用の保証された基盤として扱わない。Leaflet Routing Machineも必須依存にはせず、経路API選定後に必要性を判断する。

### 通信失敗時

背景地図が取得できなくても、写真付き一覧・詳細・住所の表示は利用可能にする。住所・経路検索では失敗を明示する。地図タイルや外部応答の一括事前取得は行わず、Service Workerは初期導入しない。

## データ更新と掲載許可

元の調査記録とは別に、スポットID単位の掲載管理を行う。状態は許可済み・確認待ち・掲載不可とし、未設定も公開対象外にする。今回の確認版の残り26件を自動的に許可済みへ変更しない。

公開用JSON・画像は許可済みのデータからのみ生成する。画面上だけで除外する方法は用いず、ZIP内のデータ・画像・ソースマップにも保留先の記事等を含めない。区・カテゴリ・タグ・座標・出典・調査年度・情報確認日は独立した項目として管理する。

更新はCSV等の元データ編集 → 検証・公開データ生成 → ビルド → ZIP再作成・差し替えを基本とする。管理画面での編集は含まない。非技術担当者がビルドなしで頻繁に更新する要件がある場合は、JSON等の直接差し替え方式と検証手順を別途設計する。

## 納品物

1. `saitama-art-map-public.zip`：配信可能なファイルだけを格納。
2. `saitama-art-map-source.zip`：ソース、lockfile、再生成・ビルド手順。公開フォルダへ置かない。非公開の掲載管理情報は必要な範囲だけ別途引き渡す。
3. 設置・更新手順、利用ライブラリとライセンス、外部通信先、検証結果。

公開ZIPの例：

```text
index.html
assets/                 # ビルド済みJS・CSS、アイコン
data/spots.json         # 掲載許可済みデータのみ
images/                 # 掲載許可済み画像のみ
config.json             # タイルURL等。秘密情報を含めない
THIRD_PARTY_NOTICES.txt
```

設置先はHTTPS、HTML/JS/CSS/JSON/WebPの配信、適切なContent-Type、必要な外部通信が条件。設定とデータは更新を反映しやすいキャッシュ設定、ハッシュ付き資産は長期キャッシュを推奨。サーバーのCSPがある場合は外部地図等の送信先と整合させる。

## 受入確認

- ZIPを空のフォルダへ展開し、開発ソースなしで静的配信できる。
- ドメイン直下とサブディレクトリの双方で動作する。
- 公開ZIPに許可未確認のレコード・画像が含まれない。
- PC・スマートフォン・拡大表示で最終カードを選択できる。
- フィルター、0件表示、解除、詳細復帰、キーボード操作が機能する。
- 現在地の拒否・時間切れ、住所検索・背景地図の通信失敗でも基本一覧が使える。
- Safari、Chrome、Edge、Firefoxの現行安定版で確認する。
