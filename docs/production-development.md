# 正式版の開発・運用

開発ブランチ：`feature/production-static-map`

## 実装

Vue 3、TypeScript、Vite、Leafletで静的配信する正式版を `web/` に実装。従来HTMLは比較用に保持し、公開・pushは実施していない。

- 地図、写真付き一覧、記事詳細、画像切り替え、OSM登録情報。
- 正規化したキーワードの空白区切りAND検索、区・カテゴリの選択、複数タグのOR検索。
- 件数、適用中条件、個別解除、0件案内、全解除。
- 現在地からの直線距離・距離順・範囲指定。許可拒否やタイムアウト時も一覧を利用可能。
- 住所検索の候補選択、キャンセル・タイムアウト・通信失敗処理。APIの正式利用条件の確認待ちのため初期設定は無効。
- 個別スポットのハッシュURL。入力住所や検索起点の座標はURLへ保存しない。
- 徒歩の経路はGoogle Mapsを開く。地図内経路表示は正式版の初期構成には含めていない。
- 一覧と詳細に独立したスクロール領域。詳細から一覧に戻った際はスクロール位置とカードへのフォーカスを復帰。
- 背景地図の失敗時にも写真付き一覧を継続して表示。

## 掲載管理

`data/publication-status.json` は元の調査IDで管理する。

| status | 確認版 | 正式公開版 |
| --- | --- | --- |
| `approved` + evidenceあり | 掲載 | 掲載 |
| `approved` + evidenceなし | 除外 | 除外 |
| `remaining-in-review` | 掲載 | 除外 |
| `pending-contact` | 除外 | 除外 |
| `denied`、未設定 | 除外 | 除外 |

現時点では未連絡11件を `pending-contact`、その他を `remaining-in-review` に設定。座標がある26件で検証する。残る26件の許可確認が完了したと独自に判定することはしていない。

正式公開時は、先方の確認済みリストと照合して `approved` と `evidence`（確認記録の参照）を設定し、`npm run package:release` を実行する。許可済みの対象が0件の場合に公開用ビルドが失敗することも確認している。

生成時は公開用の一時フォルダを作り直し、対象のJSON・画像だけを収録する。ZIP作成時にも掲載対象と未使用画像・ソースマップ等の混入を検査する。保守用ソースZIPには元データ・掲載管理が含まれるので公開領域へ置かない。

## 納品物と再生成

```bash
npm ci
npm run package:review
# 許可状態・確認記録の確定後
npm run package:release
```

- `dist/delivery/saitama-art-map-review.zip`：正式版実装の動作確認用。
- `dist/delivery/saitama-art-map-release.zip`：許可済みのみの正式公開用。現在は許可記録未入力のため未生成。
- `dist/delivery/saitama-art-map-source.zip`：保守担当向け。公開禁止。

公開ZIPを展開したフォルダはHTTPSの静的サーバーで配信できる。サブディレクトリ設置、標準的なContent-Type、キャッシュ設定については `production-install.txt` を参照する。開発用にNode.js 24系とnpm、ZIP生成・検証用にPython 3を使う。設置先ではこれらは不要。

GitHub Pagesのワークフローも `dist/production` のみを配信する構成に変更。リポジトリ全体の配信をやめ、正式公開用の掲載判定が通った場合だけ配信する。既に配信されている旧版URLはローカル変更だけでは削除されないため、切替時に確認する。

## 外部通信と設定

背景地図は地理院タイル。`config.json` のURL・出典名・出典リンク・最大ズームで変更できる。設定ファイルの出典はHTMLとして挿入せず、文字列として表示する。

住所検索は `addressSearch.enabled` をtrueにした場合のみ利用。現行アダプターは国土地理院のGeoJSON形式に対応する。入力住所は設定先へ送られるため、運用主体で利用条件・CORS・精度等を確認してから有効にする。入力と位置情報はアプリ側で永続保存しない。

経路リンクを押すと、目的地と、検索起点が設定されている場合は起点座標をGoogle Mapsに送る。ページ上でも案内する。

## 検証方法

```bash
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
# インストール済みChromeを専用の一時プロファイルで使う場合
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```

ブラウザテストは、公開ZIPを `dist/qa/map/` に展開し、開発サーバーのURL書き換えなしで配信する。専用の検証用サーバーは画像への並列アクセスを扱い、ログ出力による詰まりを避ける。外部地図の通信はテスト内で停止させ、障害時の継続利用も確認する。

Chrome実画面でもサブディレクトリから読み込み、26件目の詳細表示・一覧復帰・0件検索・タグ反映を確認した。

2026年11月18日の結果：型チェック成功、単体テスト12件成功、専用プロファイルのChromeによるブラウザテスト10件成功（PC・iPhone 13相当の画面サイズ各5件）。最終カードの画像読み込み、詳細から戻った際のフォーカス復帰、0件表示と解除、タグ検索、現在地の取得・拒否、起点解除、住所候補選択、地図通信失敗時の継続利用を確認した。位置情報と住所候補はテストデータを使用し、実際の個人の住所・現在地は使用していない。

Safari・Firefox・Edgeやスマートフォン実機での確認は別途必要。

## 依存ライブラリの監査

2026年11月18日の `npm audit --omit=dev` は0件。初回監査で報告されたcsv-parse・Vitest等を修正版へ更新し、Node.js 24系に揃えた。

全依存の監査には開発用のpicomatchを起点とするhigh 7件（依存先への伝播を含む）が残る。調査時点の公式レジストリ最新picomatch 4.0.7も対象のため、無理なダウングレードは行わない。開発・ビルド・テスト時の依存であり公開ZIPには含まれない。開発サーバーは127.0.0.1に限定し、これらのツールへ外部から任意のglobパターンを渡す機能は設けない。更新時に再監査する。
